# 公开发行的来源与维护方式

本仓库的每个版本都由上游 AI Hub 的某个提交**自动导出**，不是手工复制。导出时记录的上游版本与提交号写在 `community-edition.json`。

## 导出做了什么

1. 只从上游已经提交的内容出发，不读取维护者工作区里未提交或未跟踪的文件。
2. 按清单只取程序文件（`core/`、`main/`、`renderer/` 与运行所需脚本），删除私人模块整文件。
3. 上游代码里私人模块的接线点用成对的注释标记包住，导出时整段删除；少数位置换成社区版的实现（例如 API 默认指向官方地址、数据目录独立、不改全局权限模式）。
4. 注释与界面文案做脱敏：去掉维护者的名字、本机目录结构与私人项目名。
5. 覆盖本目录的公开文档、安装脚本、测试与 CI。
6. 闸门：剥离标记必须全部处理、全部 JavaScript 通过语法检查、相对 `require` 与页面引用都能解析、身份与私人服务的泄露规则零命中、`scripts/audit-public.js` 通过。任何一项不过，导出失败。

## 与上游的差异

- 私人模块（个人投研、学习陪伴、投资相关的群聊场景与 prompt、公司内部中转、本机专用工具与生图池、私人网关）不在发行文件里。
- CLI 状态回报（hook）改由 Windows PowerShell 执行并由 Hub 解析，上游使用 Python。这样便携版不需要 Python 或 Node。两边的解析结果由上游的契约测试逐字段比对。
- Hub 启动的 Claude 会话带 `--permission-mode bypassPermissions`；上游把同样的档位写进全局 `~/.claude/settings.json`，社区版不改用户的全局配置。
- 数据目录 `%USERPROFILE%\.ai-hub-community`、产品名、Windows 应用标识和快捷方式都与上游分开，两者可以并存。
- 默认不使用本机代理，API 模式指向官方地址。

## 维护规则

- 不要把上游仓库直接镜像推送到这里，也不要把私人工作区整体复制进来再靠 `.gitignore` 补救。
- 新版本由上游导出后，在独立目录自带依赖运行 `npm ci`、`npm test`、`node scripts/audit-public.js`、`node tests/e2e-community-cdp.js`，通过后再提交、打 tag，由 CI 构建和发布。
- 程序配置、token、真实会话、个人报告和本机安装日志不进入公开仓库或 Releases。

不宣称无需账号、无需网络或所有功能零配置。AI 账号授权和模型权限来自使用者本人；使用成本由所选的提供方决定。
